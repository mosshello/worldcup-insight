## 执行规则

- 用户批准方案后开始 T00；本轮只创建方案与任务文件。
- 每项任务结束记录：改动、实际测试、产物路径、尚存缺口、是否影响后续任务。没有证据不标完成。
- 任务是可独立审查的工作包，不表示本轮创建多个聊天或启动后台代理。跨文件任务优先顺序执行；接口固定后可安排独立工作，写共享存储、契约和迁移时不得竞争。
- 每个阶段保持应用可用；不提交/推送、不自动替换已有观察模型。若执行范围随后授权新增赛事模型选用，仍必须以独立操作留痕。
- 工作区已有大量未提交改动，先记录归属；不能为获得干净基线而重置或删除。
- 下列建议模块名允许在 T01 小幅调整，任务责任和验收条件不得因此丢失。

## T00：基线与契约

**改动范围**：`docs/football-system-contract.md`、迁移/审计辅助脚本、验收记录。不改训练参数。

**实施**：
- 清点 Git 改动和运行服务；记录数据库位置、已有预测数量、输入摘要、模型/数据文件摘要及选用指针，记录当前页面资源版本。
- 使用 SQLite 一致性备份创建恢复点；备份产物及规则配置。用户笔记与收藏也纳入校验。
- 将批准后的按模型输入检查原则写入现行契约，明确替代旧全量资料门槛；旧实施记录保留。

**验收**：备份可在独立目录打开；基线报告不包含密钥；不得重写现有归档或自动提交。备份没有完成则不得进入真实迁移。

## T01：数据口径、API 与界面原型

**改动范围**：`.design/football-data-model-refactor/`、接口说明和类型定义草案；此时不发布前端。

**实施**：
- 根据真实组件、TDesign tokens、截图重建现状对照，再设计目标六页；提供桌面和移动版，以及首次接入/部分覆盖/无模型/当前模型与候选不同等状态。
- 固定可预测分母、日期口径、数据集数量、模型报告关联、问题数去重规则。
- 固定 v2 查询/写入 schema、错误码、版本比较、幂等与旧 API 兼容边界；范围外未知字段保持未知。
- 队伍管理的全局身份与赛事参赛范围分别设计，不把顶部赛事选择器当所有对象的所有权。

**验收**：原型标明演示数据；1392/1391 示例来源可核实，未取得的今日可预测数用占位而不是编造；逐页操作对应真实或明确待建接口。界面仍保持简短中文、直角和单行表格。

## T02：身份与参赛关系

**改动范围**：`catalog.py`、`store.py` 增量迁移、建议新增 `identity_registry.py` / `identity_service.py`；`league_data.py` 和来源匹配入口适配。

**实施**：
- 建立球队、赛事规则版本、来源映射、赛季参赛记录和比赛修订关联。
- 旧赛事配置以种子导入；明确登记仓库为切换后权威源，保留 catalog 兼容接口，解除导入时静态赛事集合依赖。
- 旧比赛/球队来源 ID 与模型内部 ID 通过旁挂映射关联，不改旧产物；相同名称不自动合并。
- 未登记赛事建立发现记录，禁止以不可靠的来源 league_id 直接合并不同赛事，训练口径保持未知。

**验收**：同队跨赛事共享身份但参赛记录独立；同名不同队不混淆；冲突映射不能启用；迁移重跑幂等；旧模型摘要不变。新库中的球队归属信息不足不妨碍经核验的一线队身份使用。

## T03：来源、采集与问题处理

**改动范围**：`history_pipeline.py`、`sources.py`、`fundamentals.py`、`context_merge.py`，建议新增 `ingestion_jobs.py` / `source_adapters.py` / `data_issues.py`。

**实施**：
- 定义适配器输入为来源能力与赛事/赛季/范围，输出原始响应引用、统一记录、覆盖和错误，不以配置存在表示接入成功。
- 持久化任务、批次、重试关系及截止位置；支持分批恢复、超时、限流退避，不能重复生成同一事实。
- 结构化问题记录明确严重程度、对象、来源、证据、处理状态与解决版本。
- 现有日韩采集接入统一接口，保留已验证逻辑；启动亚冠历史源范围、赛季/阶段、90 分钟与球队覆盖核查。

**验收**：失败保留旧事实原时间；成功空响应不沿用已撤回内容；403/429/部分响应可解释；来源缓存与数据新鲜度分开；亚冠源失败不影响日韩采集。

## T04：数据集与验收

**改动范围**：`research_dataset.py`、`training.validate_dataset`、`model_registry.import_competition`，建议新增 `dataset_service.py`。

**实施**：
- 生成独立验收报告，逐条列纳入/隔离及原因，绑定来源批次和固定映射/规则版本。
- 固定数据摘要、样本时间范围、使用范围、半场/盘口覆盖；保留当前 datasets 内容寻址文件。
- 当前数据版本和模型引用版本分开；版本差异展示新增、删除、修正和隔离变化。
- 复核日职差额的真实原因；无新证据不解除开球时间隔离。

**验收**：采集唯一记录可与纳入/隔离清单对账，重复原始记录单列不重复计场；跨赛事样本拒绝；加时/点球不混为 90 分钟；历史可用时间假设明确；改变当前指针不改变旧数据版本。

## T05：模型输入规范与预测条件

**改动范围**：`model_methods.py`、`training.py`、`quality.py`、`readiness.py`，建议新增 `feature_contracts.py` / `prediction_eligibility.py`。

**实施**：
- 为现有各方法定义真实必需输入、可选输入、支持玩法、球队样本门槛、时间与场地/阶段适用政策。
- 统一历史和实时特征计算边界；旧方法保持原数学行为，只有显式新版本才能改变特征/参数。
- 将资料覆盖与模型资格分开；缺完整伤停不再阻断不依赖该字段的基础模型。
- 报价校验独立返回；未知/不支持玩法不生成占位概率。

**验收**：缺辅助字段仍可预测；缺必需字段必须阻断；无半场数据不阻断全场目标；未知球队/样本不足有原因；未来和后补事实不进入真实赛前输入；无需先通过报价检查才能读取模型状态。

## T06：训练、评估与候选比较分离

**改动范围**：`training_jobs.py`、`model_evaluation.py`、`model_registry.train`。

**T06-A：时间协议与样本清单**（先完成）
- 固定训练、验证、保留测试范围、预测时点、阶段政策、缺失策略、更新频率及各段样本摘要。
- 固定模型测试与滚动策略回测单独定义；训练前明确选优指标，不能看完测试再换配置。
- 同赛事可用合格历史多赛季；不同赛事隔离；不同球队对阵可以在同赛事攻防模型内共同拟合。

**T06-B：单独训练任务**（依赖 A）
- 新任务在锁内固定数据摘要、训练窗口、算法及参数，持久保存 task_id/run_id；单次训练不再隐式跑全部九组候选与回测。
- 保存运行历史、产物、错误、中断和重试；训练任务输入样本与评估样本清单分别引用。
- 默认单算法，算法配置之间不共享拟合参数；可复用经过核验的原始事实和确定性特征缓存。

**T06-C：独立评估与候选比较**（依赖 A、B）
- 创建固定产物评估任务，不重训该产物；校验评估比赛位于拟合范围之后。任何状态更新须在评估协议里明确。
- 创建滚动策略回测任务，每折只用截止前已可用样本，保存子模型/特征快照、截止时间与逐场预测。
- 候选比较父实验管理独立训练/验证子任务；默认不读取保留测试段。冻结赢家后按预先定义协议进行保留测试。
- 报告明确 `evaluation_kind` 与被评估对象：固定产物摘要或策略摘要及逐折产物；同时报告共同样本指标、各候选覆盖及跳过原因。
- 旧测试段全部保留历史探索标记。测试段前序赛果只有在预先定义的滚动更新策略和可用时间允许时才能进入后续折，不得据此调参。

**T06-D：最终重训与报告关联**（依赖 C）
- 明确触发最终重训，使用冻结配置和截至该时点可用数据，产生新的模型版本。
- 关联实验和策略评估作为依据，不把回测报告的评估对象改写为最终产物；该版本直接前瞻成绩从后续真实归档积累。
- 继续兼容 `full_time` / `had`，准确显示当前按胜平负验证指标选优；不暗中改变优化目标。

**验收**：训练期间导入不改变输入；同赛事排他，不同赛事可独立调度；单算法训练不会启动全候选评估；中断不标成功；训练不改选用；未来/后补赛果、预处理泄漏、目标比赛进入训练均有失败用例；测试前冻结配置；最终重训版本不冒认旧回测成绩；零市场样本不产生伪指标。

## T07：模型与选用

**改动范围**：`model_registry.py`、新选用历史表、指定运行报告 API。

**实施**：
- 按 run_id 返回模型及关联报告；明确区分直接评估和策略历史依据，不用“最新报告”替代，也不将最终重训产物冒认为回测各折产物。
- 迁入已有选用记录，保留原 run_id；新增选用修订、停止观察记录和并发版本比较。
- 本期每赛事一个默认模型；显示每种玩法支持状态及两队覆盖，不静默拼接别的版本。
- 旧模型旁挂能力规范，不改旧 model.json/evaluation.json 摘要；无法证明的能力不标支持。

**验收**：韩职当前泊松与候选动态 Gamma 的报告不串；同名算法不同运行可区分；跨赛事选用拒绝；并发选择返回冲突；停止观察不删除模型；数据集刷新不使旧选用被自动清空。

## T08：足球预测、市场参考和复盘兼容

**改动范围**：`service.prediction`、`enrich_detail`、`predictor.py`、`briefing.py`、`football_markets.py`、复盘/AI 输入适配、`MatchWorkspace.vue` 等消费者。

**实施**：
- 将足球预测设为新预测结果的明确主体，市场参考单独计算；状态来源核验与体彩是否在售解耦。
- 新归档 schema 保存固定选用、模型、比赛修订、特征/事实快照和实际检查时间。
- 归档前检查时间、身份、选用和必需输入，保证失败时无半条归档；幂等键与明确的新版本操作区分。
- 新旧归档分支读取；旧市场参考继续显示原类型，复盘与 AI 解释只读对应归档。

**验收**：无赔率但基础模型有效可以归档；无模型只有赔率不能生成足球归档；处理期间开赛/改期/换模不能错存；旧预测和输入摘要不变；新旧指标分组；LLM 没有进入赛前计算。

## T09：六页界面联调

**改动范围**：拆分 `ModelWorkspace.vue` 为概览、球队、来源、数据集、训练和模型子组件；`api.js`、`competition_workspace.py` 及新查询服务；比赛页对应状态。

**实施**：

**验收**：所有数字可对账；当前使用与候选不串；切换赛事后错误响应不能覆盖新赛事内容；空态/部分覆盖/失败/并发操作/手机宽度均通过；不改变笔记及历史归档。

## T10：亚冠真实接入与当日赛事核查

**改动范围**：新赛事登记、来源适配配置、验收数据与本赛事新产物、真实核查报告；不改已有日韩选用。

**实施**：
- 核实来源身份、历届赛事连续性、赛季阶段、90 分钟口径、中立场与回合适用政策；不能混入亚冠二级赛事或国内联赛凑样本。
- 核查目标双方的独立样本覆盖；仅映射成功不等于模型学过球队。
- 取得足量合格数据后独立训练、评估；未达最低门槛如实列缺口，不降低门槛冒充完成。
- 根据已批准范围单独选用可用候选，执行尚未开赛比赛的真实预测检查；先前已开赛的目标不能补造赛前归档。
- 发现执行日全部收录赛事，对欧冠/其他赛事逐一给出接入矩阵，记录来源、规则、样本、模型及球队覆盖状态。其他赛事能完成闭环则沿同流程处理，无法完成须逐项说明。

**验收**：至少目标亚冠纵向链路有真实证据才能称亚冠接入完成；如外部条件不足，T10 为阻塞/部分完成，系统基础验收与赛事验收分别报告。不能用三场样本、合成数据或其他赛事模型替代。

**验收**：输出系统改造与赛事接入两份结论，列通过/失败/未执行及证据；任何历史内容被改写、跨赛事污染、时间泄漏或市场冒充模型均阻止发布完成。

## T12：第二期增强数据与特征

**实施范围**：球员主档、带有效期的归属/租借/转会、赛事报名、停赛、伤病、预计和确认阵容、历史 xG 等。

- 名单公布事实独立采集；归属、报名、规则资格和身体状态分别判断，伤病不等于规则禁赛。
- 对每个特征提供历史和实时可用性证据，定义缺失处理与覆盖；新增模型版本做同样本消融比较，报告覆盖损失。
- 未经过评估的跨赛事休息/实力等特征继续只展示；本期不自动引入跨赛事训练。

**验收**：存在真实历史特征而非只补今天数据；时点正确；未用特征不标已入模；增强模型不自动替换基础模型；新数据来源失败不损坏基础链路。
