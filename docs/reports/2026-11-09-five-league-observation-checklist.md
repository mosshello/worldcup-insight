# 五大联赛观察与预测增强：调整及验收清单

日期：2026-11-09。状态：实施及验收中。仅有实际代码、数据和测试证据的条目可完成；未来效果、尚缺数据不以功能测试代替。总方案见 [能力复核](2026-11-09-football-system-capability-review.md)，执行约束见 [系统契约](../football-system-contract.md)。

## 验收纠正（2026-11-09）

十二项整体未完成。T03真实亚洲盘连续覆盖、T04赛前人员与完整负荷、T05新增情报进入数值增强模型、T06对应增强实验仍有实施缺口；T02未来节点及T11前瞻效果另需实际发生的记录，T12整体不能收口。代码测试通过、预测生成成功和候选未提高准确率，都不能替代这些验收。

当前增强组只使用已固定的xG、近期进失球和休息特征。AI提取保留并校验已有数值，新增人员消息尚未形成经训练、独立验证且实际进入该组的数值特征。历史人员使用代理的回测不能视为完整赛前伤停、预计分钟、替补实力及个人跨赛事负荷方案的效果结论。

## 范围与已明确的方向

- 新增独立的“五大联赛观察”板块，覆盖英超、西甲、德甲、意甲、法甲；复用现有赛事、球队、数据、赔率、模型及归档能力。
- 时间按每场实际开赛时刻倒推。上轮“每天上午10点早报”的设想不作为本次默认任务；不能把北京时间晚上10点写成所有比赛统一降水时间。
- 建议的固定预测版本为：可核实的开盘观察、赛前60分钟、赛前15分钟。另记录实际盘口变化事件。赛前90～30分钟为建议重点采集窗口，不宣称五联赛已验证的统一峰值规律。
- 四组对照为同期市场参考、现有基础模型、AI事实增强模型、AI独立判断。观察时点与预测来源是两个独立维度，不能混为一列或一个成绩。
- 胜平负、让球、总进球、比分、半全场全部保留；每个模型按真实支持能力运行，未支持玩法不伪造输出。
- 现有模型与功能继续使用；训练只产生候选，研究试验不自动更换生产选用，历史预测、结算和报告不覆盖。

## 逐项任务

### T01 观察数据与实验隔离

- [x] 复用比赛和球队身份；新增按赛事、比赛、实验、预测来源、观察节点和实际生成时间区分的观察记录。
- [x] 复用历史不可变归档方式；新增快照，不覆盖当前扫盘首份记录或既有回测依赖。
- [x] 冻结输入截止、实际采集/生成时间、模型版本、规则、盘口线和证据索引。输入摘要与原始来源可追溯。
- [x] 同场多时点比较固定模型/实验版本；切换版本另起实验系列，不能把模型变化说成赔率或情报影响。

验收：同场四组、三个节点能同时存在且不串档；五联赛互不覆盖；重复任务幂等；旧记录哈希不变。

### T02 五联赛赛程和观察节点

- [x] 观察目标来自五联赛赛程，不只限体彩选入的比赛；是否有体彩报价和是否可预测分别计数。
- [x] 实现开盘、T−60分钟、T−15分钟的独立后台任务；采集计划覆盖更早阶段和临场阶段。
- [x] 有真实初盘证据才标“开盘”；只有首次采集就如实标记；报价发布时间和首次采集时间分别保存。
- [x] 初盘在系统接入之前的比赛，不使用今天资料回填成旧时点预测。
- [x] 处理跨日、夏令时转换、延期、提前开球、取消、改对阵和无赛程日。页面显示北京时间与实际开球日期。
- [x] 处理离线、失败重试、服务重启、临场并发；记录时点偏差。错过节点不得事后补造准点预测，未开赛的晚到运行必须独立标记并排除原节点严格对照。

验收：后台按实际开赛时间触发，不依赖打开页面；开赛后拒绝新建赛前记录；取消/延期不会生成重复或错配记录。

### T03 盘口变化与降水观察

- [ ] 体彩SP与亚洲让球盘分开；亚洲盘先落实可取得且可使用的数据源与时间精度，不以体彩整数让球冒充。
- [x] 对同公司、同市场、同盘口线、同结算规则记录两边报价及变化；升降盘和单纯水位变化独立记录。
- [x] 保存初始值、最近值、发布/采集时间及持续时间；处理单点、缺测、陈旧报价、回调反转和来源分歧。
- [x] 阈值、持续条件、去重、冷却、训练/验证和不可变报告已实现；真实数据不足时拒绝拟合及启用，不生成任意有效信号。
- [ ] 按联赛和距离开赛的时间分桶，统计变化发生率、幅度与持续性；核实真正活跃的时间窗。不能用不等长窗口总变化量直接宣称单位时间最活跃。
- [x] 降水事件进入单场时间线；固定节点对照覆盖全部目标，不能只挑发生降水且命中的比赛评分。

验收：换盘口线不会被识别成同盘口降水；没有实际资金数据不显示“主力/散户资金”；记录价格变化不推定操盘意图。

### T04 赛前事实、球队与人员

- [x] 盘点已有历史比分、xG、球员分钟、教练、名册及赔率；按历史赛后、真实赛前和回溯假设区分。
- [ ] 完善时间有效的球队—球员—教练关系，核对转会、注册、赛事资格和停赛适用范围。
- [ ] 完善伤停、预计/确认首发、预计分钟、位置、替补能力及阵容延续性；保留未知与冲突。
- [ ] 联结联赛、杯赛、欧战及国家队出场的负荷事实，处理休息、旅行、加时和轮换；不因此跨赛事混合训练标签。
- [x] 为消息保存来源、发布时间、首次采集时间、适用比赛、有效期和修订；转载去重。

验收：查到人员台账不等于已有赛前阵容；缺失伤停不等于无人伤停；原模型不需要的增强字段缺失，不阻断原模型。

### T05 AI情报提取与独立预测

- [ ] AI提取路线生成有证据的结构化事实，再经规则核验进入增强特征；不让自由文本直接改概率。英超FPL赛前报告到数值特征、独立训练、后台分发和AI真实调用已完成；其他联赛及完整人员情报仍未完成。详见[英超单联赛验证](2026-11-09-epl-pregame-personnel-results.md)。
- [x] AI独立预测在研究板块运行，固定模型版本、提示词、证据和输出协议，记录成本、耗时、失败及重试。
- [x] 不显式提供赔率与提供同期赔率的试验分开；检索泄露的市场信息要记录，不能虚称完全市场盲测。
- [x] AI独立组不读取其他候选最终预测；不把解释写得详细当作预测有效。
- [x] 来源可信度、事实不确定性与赛果概率分别保存；格式和概率校验失败保留失败记录。
- [x] 仅能输出胜平负时明确能力范围；如扩展五玩法，需单独定义比分/半场条件分布及一致性校验协议。

验收：四组真实产物可区分；未运行、无能力、调用失败不显示成成功预测；研究运行不改变生产训练、结算或选用。

### T06 现有模型保留与增强候选

- [x] 保留DC/Poisson、Elo及已有合格候选；复用现有xG、交锋研究与失败结果。
- [x] CatBoost、LightGBM等新增输入时生成独立特征版本、重新训练与评估，不往旧模型塞字段。
- [ ] 优先验证人员/替补、完整负荷、对手调整后的机会创造与防守；逐联赛消融，检查重复信息。
- [x] 已完成交锋连胜/多平在xG、主客、人员使用和教练代理之外的独立消融，保留无稳定收益结果；战术对位无合格观测特征，未建立或宣称有效。
- [x] 市场过度反应、热门偏差、新闻与价格分歧列为候选假设；无有效证据不生成“诱盘加减分”。
- [ ] 阵容未知时可研究有依据的情境分布；不凭空估计出场概率。融合与校准另建候选，各原始组保留。
- [x] 最终拟合纳入截止前全部合格历史并记录排除原因；对应测试目标不进入该次拟合。不以“全量”要求强行使用无关字段。

验收：增强失败不影响基础预测；没有稳定提升的候选不晋级；每个赛事训练、产物和选用保持独立。

### T07 五玩法与历史结算

- [x] 胜平负、整数让球、总进球与比分复用一致全场比分分布；市场参考和足球概率分别保存。
- [x] 半全场单独检查半场能力；状态/进球时序增强需独立验证，不把现有简化分配称为已实现的动态模型。
- [x] 90分钟、加时、点球、晋级分开；历史预测使用当时冻结的盘口线和结算规则。
- [x] 正式赛果修正追加结算版本；不能重新训练后回写旧预测以匹配赛果。

验收：五玩法概率及结算回归通过；分类器不冒充比分模型；不同玩法首选不强制互斥，也不拼成必然一致的单一比分。

### T08 新“五大联赛观察”页面

- [x] 独立导航入口；五联赛、比赛日期、玩法、观察节点和预测来源可筛选。
- [x] 默认每场一行，开盘、T−60、T−15并排比较；通过玩法/来源筛选控制宽度，不一次铺开全部维度。
- [x] 单场详情展开完整五玩法、四组概率、盘口时间线及证据。实际降水事件放详情。
- [x] 单选命中、多选覆盖、未预测、待赛果、失败分别统计；不能给“同场多个版本任一命中”记一场成功。
- [x] 沿用TDesign蓝色、直角、桌面单行表格及手机适配；主屏只放操作、结果、必要状态和时间，方法/版本/缺口进详情。

验收：筛选统计分母一致；手机没有不可操作的超宽内容；多个观察版本不把同一比赛伪装成多场独立样本。

### T09 现有页面衔接

- [x] 数据与模型：显示实际入模字段、覆盖、报告与候选/选用状态，链接观察结果。
- [x] 比赛分析：已增加有来源的人员、历史阵容使用和跨赛事球队负荷，链接单场观察历史；战术对位仍无合格可观测特征，不宣称已建模。
- [x] 原扫盘：保留现有业务和归档；研究对照集中在新板块，不把实验记录混进原成绩。
- [x] 复盘与回测：按来源和节点查看当时完整预测，不用当前模型重建原答案。

验收：原比赛、比分、扫盘、复盘及模型页面回归通过，老记录入口仍可用。

### T10 后台运行与性能

- [x] 采集、AI和预测由可恢复的后台任务执行；页面只读结果，不在GET请求中临时跑AI或训练。
- [x] 设置缓存、超时、并发限额、去重、重试及费用预算；同一证据不无意义反复推理。
- [x] 赔率采样频率与来源实际更新/限制匹配；缓存命中不刷新原成功时间，不声称秒级实时。
- [x] 五联赛任务互不阻塞；外部故障提供真实缓存时间和失败状态，不无限转圈。

验收：正常、断网、接口失败、AI超时和多场同时临场均测试；性能门槛按现有服务基线预先确定并记录，不能仅凭新空白测试页宣布达标。

### T11 评估、成本与模型晋级

- [x] 保留四组同场、同时点对照；历史探索与真正前瞻分开，锁定验证/测试窗口及选参规则。
- [x] 每个联赛、玩法、节点分别报告单选准确率、多选覆盖、Log loss、Brier、校准、未预测与失败数量。
- [x] 同时报告共同有效样本和全目标覆盖；同场多时点的统计依赖需处理，不独立重复计样本。
- [x] 记录AI真实Token、耗时、延迟、缺失和有有效期的价目估算，账单未知保留未知；新赛季、换帅、轮换分组已实测，升班马资格未核验时保留unknown，未伪造分组成绩。
- [x] 事先确定可接受改善、稳定性、不确定区间与停止规则；无稳定增益继续保留基准。
- [x] 候选选用按赛事单独执行；只影响之后的新预测，保留停止/回退记录。

验收：不利用测试赛果挑提示词、节点、阈值或融合权重；不以单选准确率直接推定盈利；无实际报价不编造收益。

### T12 综合验收与发布核对

- [x] 隔离：跨赛事、跨模型、跨时点、跨盘口和新旧归档均不串用。
- [x] 时间：临近开球、已经开球、延期、跨日、时区、首发晚到、离线错过节点均覆盖。
- [x] 数据：空资料、矛盾身份、同名球员、旧闻、报价换线、单点历史及无体彩市场均覆盖。
- [x] 模型：原模型可用/无模型/能力不支持/增强输入缺失/AI失败分别验证，无静默回退。
- [x] 页面：桌面和手机逐页核验导航、筛选、详情、时间线、导出及加载失败恢复。
- [x] 发布时核对用户当前打开的本地预览实际加载新资源；无未保存输入才刷新。
- [x] 已交付逐项实现、真实采集/训练/回测/页面证据、失败项及仅本地部署范围；未完成的真实事实及效果验收继续单列。

## 执行依赖与范围控制

先做T01/T02的观察基础和T03/T04的数据核实，再接T05/T06；T07/T11随候选开发同步验证。T08/T09可先基于真实状态提供页面，不能用假数据冒充已跑实验；T10贯穿全过程，最后执行T12。不得因页面做完而跳过数据、模型与前瞻验收。

战术交互、半全场动态模型和市场异常先交付研究结果，不保证本轮即获选用。完整球探/医疗系统、自建全场视频追踪、从零训练大模型、无证据多AI投票和自动下注不在本次范围。

## 观察时点的调研依据

本清单的T−60/T−15是建议的固定对照节点，不宣称最佳降水时点已经被验证。首发发布应另存实际时间，不能统一硬编码所有联赛为同一分钟。

- [英超官方首发时间说明](https://www.premierleague.com/en/news/4081650)：自2024/25赛季在赛前约75分钟发布首发，为关注临场提供明确的信息事件依据。
- [Mysports.AI初步研究](https://mysports.ai/en/research/soccer-lineups-odds/)：商业平台自报的首发与价格变化研究，主要市场与时间代理有局限，不作为所有亚洲盘的已验证规律。
- [49场价格变化分析](https://pinnacleterminal.io/blog/odds-movement-before-kick-off)：独立工具商单周末的Pinnacle胜平负研究，不是Pinnacle官方结论，不代表五联赛亚洲盘的大样本验证。
