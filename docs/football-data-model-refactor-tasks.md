## 2. 通用实施约束

- 保留未提交用户工作，不 reset、不删除已有数据、不自动提交推送。方案批准后才实施。
- 沿用现有技术栈和文件注册表，不在本期迁移为数据库注册表或引入大型 ML 平台。
- 代码、接口、迁移和页面改动同步记录；测试使用独立 SQLite、训练根目录和来源缓存，防止模拟数据写入真实环境。
- 主方案中的时序、归属、失败和回退场景必须分配到任务验收，不能仅以测试总数或 HTTP 200 证明业务正确。
- 自动编排不等于混合训练：可以有父实验，但不同赛事/算法的任务和模型参数独立，训练不会自动选用。
- 阶段失败停止依赖写入，保留现场和日志；外部条件阻塞与代码失败分别报告。

## T00：基线与恢复准备

范围：审计脚本、备份清单、验收记录；不改变业务规则。

- 记录当前 Git 工作区、服务目录、SQLite、训练目录、页面资源、已有比赛/预测/笔记/收藏、数据和模型摘要及选用指针。
- 使用 SQLite 一致性备份，并核对文件产物；在独立目录验证备份可读。动态缓存允许自然变化，不用整库文件哈希代替不可变归档校验。
- 记录当前契约与目标差异，暂不把尚未实现的新规则标成现行。

验收：旧归档及输入逐条摘要、产物逐文件摘要可比较；备份没有完成不得真实迁移。不得暴露密钥。

## T01：先验证可行性，再固定接口与原型

范围：来源只读核查、`.design/football-data-model-refactor/` 原型、schema 与协议文档。

- 亚冠核查赛事 ID、历史阶段/赛制连续性、90 分钟结果、中立场/两回合口径、赛季数、实际目标球队样本与使用范围。未知留空，形成可行性/阻断矩阵。
- 核查执行日所有已收录赛事及未知代码，不再固定场次列表。为后续真实闭环记录来源范围和时间。
- 固定核心对象、API 错误码、幂等、修订检查、统计分母和评估对象 schema。资源至少区分数据快照、样本视图、训练任务、评估任务、产物和选用。
- 从真实 Vue/TDesign 组件还原现状，再制作六页目标 HTML 原型和关键异常态。线框/演示数字明确标注，不称实际已接入。
- 原型允许“新建实验”显式自动组织阶段；不强迫用户机械点击多个任务，不保留不透明的一键训练回测。

验收：新赛事可行性有真实证据或明确缺口；每个页面操作有对应服务；字段有来源或待建说明；模型成绩归属清楚。外部数据不足提前记录，不通过造样本解除阻碍。

## T02：身份与规则版本

范围：`catalog.py`、`league_data.py`、来源匹配入口、SQLite 增量迁移；建议新增身份仓库与服务。

- 新增球队、映射、参赛和比赛修订关系，保留旧 ID，通过关联桥接历史训练球队 ID。
- 现有赛事配置继续作为权威；通过唯一服务原子更新并生成不可变规则版本，移除导入时静态缓存造成的过期读取。数据库仅作索引，不双向写配置。
- 未登记赛事按来源命名空间独立发现，不根据通用 league_id、队名或时间猜归属。
- 规则明确联赛/杯赛、阶段、90 分钟、中立/主客及回合适用范围；未实现能力不能默认为普通主客联赛。

验收：同队跨赛身份共享而参赛独立；同名不同类别不合并；冲突映射禁用；改期保留修订；迁移幂等；原模型/数据/选用不变。

## T03：来源采集与问题记录

范围：`history_pipeline.py`、`sources.py`、`fundamentals.py`、`context_merge.py` 及采集任务/问题服务。

- 适配器输出原始记录引用、来源批次、统一事实、覆盖范围和错误；配置存在不代表接入成功。
- 任务持久化状态、截止位置、重试、父子关联与租约/心跳；重复任务幂等。网络调用不占数据库长事务。
- 问题保存对象、原因、证据、严重程度与处理版本；成功空响应、缺字段、请求失败区分处理。
- 将现有日韩采集纳入统一协议，开始亚冠来源适配；保留已验证行为，不重采覆盖旧模型输入。

验收：超时/403/429/部分响应/成功空响应均可解释；旧时间不被刷新伪装新数据；跨赛事失败隔离；重启不把中断任务标完成；重复采集不重复算比赛。

## T04：数据快照、样本政策与历史读取

范围：`research_dataset.py`、`model_registry` 数据导入/读取、验收报告和版本索引。

- 独立生成纳入/隔离清单与来源批次；保留日职一场开球时间冲突，除非取得新核验证据。
- 数据快照不绑定某一种算法的唯一特征矩阵；样本/特征视图按任务协议、版本和时间生成并固定摘要。
- v2 单赛事导入严格校验；v1 显式批量分区兼容，报告所有分区处理结果，不静默丢弃。
- 旧产物读取按固定历史政策和摘要校验，当前政策控制新数据/训练/使用。暂停训练不使历史归档不可读。
- 使用范围、缺失字段、时间假设分别保存；新数据指针不改变旧版本或运行中任务。

验收：数量对账包含重复来源记录、唯一比赛、纳入、隔离；90分钟口径正确；规则更新不使旧文件无理由失效；混入其他赛事拒绝或在明确批量接口分区；旧摘要不变。

## T05：输入规范与资格检查

范围：`model_methods.py`、`training.py`、`quality.py`、`readiness.py` 和特征/资格服务。

- 逐方法核对实际输入、状态更新、支持玩法和阶段/场地/球队限制，不从算法名称推断能力。
- 保留旧产物特征冻结语义；新实时特征或状态更新政策需要新版本和匹配的评估。
- 分开比赛身份、模型、必需输入、赔率质量和辅助覆盖，返回结构化阻断与提示，不循环依赖总 can_predict。
- 原有工作流最低样本、球队覆盖、有效期政策先保留并按职责检查；不能为试点通过而静默降低。

验收：无伤停但模型不用它可计算；缺必需字段阻断；未知球队/中立场/不支持阶段显式返回；无半场/盘口只影响相应玩法；未来事实、预处理泄漏和训练/预测特征不一致测试必须通过。

## T06：训练、评估与实验编排

范围：`training_jobs.py`、`model_evaluation.py`、`model_registry.train` 及任务/产物接口。

### T06-A：协议与样本边界

固定赛事、数据/特征/标签/规则版本、样本清单、时间分段、预测时点、候选、选择指标、更新政策、最小覆盖及新球队规则。旧已查看测试段保持历史探索标记。

验收：样本归属可重建；目标比赛/未来结果不能进入同次拟合；候选比较显示共同样本和各自覆盖，不拿不同比赛集合直接判胜。

### T06-B：拟合任务与不可变产物

单算法拟合按固定输入运行，不隐式调用整套比较。保存代码/依赖版本、种子、样本、参数、产物摘要。先写临时产物校验后原子发布，最后更新任务；中断通过对账恢复。

验收：运行时新导入数据不改变输入；中断不产生可选半成品；同赛事任务排队，不同赛事独立；父任务不持有阻塞子任务的同一排他锁。

### T06-C：评估任务与候选比较

固定产物评估绑定产物与输入政策；滚动评估保存协议、逐折产物、截止与预测。候选比较父任务仅组织独立任务，默认验证选优后才评估保留段；明确允许执行哪些阶段，不自动更换模型。

验收：固定模型评估不会重新拟合参数；滚动策略只能用截止前已可用赛果；预处理/校准/状态更新同样受截止约束；重试只重跑失败依赖；报告可回放至每折输入与模型。

### T06-D：最终重训与来源关联

显式选择最终重训或在父实验开始前声明该阶段。新产物引用冻结配置/策略依据，不能修改旧报告的实际评估对象。新版本前瞻成绩从之后归档积累。

验收：重训不改选用；报告区分直接产物评估与策略历史依据；同一模型回测包含过训练比赛时不能标样本外；市场零样本不伪造指标。

## T07：模型能力与单独选用

范围：`model_registry.py`、能力元数据、文件指针更新服务与可重建审计索引。

- 保留文件注册表/指针为权威，新增选用修订和操作记录，不在数据库再建第二个权威。短提交锁独立于训练长锁，跨进程采用一致锁顺序。
- 旧 model.json/evaluation.json 不重写；旁挂元数据说明旧模型输入、报告类型和限制，无法证明的能力保持未知。
- 当前使用、候选、历史产物、直接评估、策略依据和前瞻证据分别关联，不用 latest 报告代替。
- 每赛事一个默认模型，按其真实支持玩法响应；选用验证技术适用和使用范围，显示研究限制，不声称效果合格。
- 暂停训练、停止观察、历史可读分别处理。模型数据更新不会自动清空原选用。

验收：日韩当前选用不变；韩职泊松与 Gamma 候选报告不串；跨赛事选用拒绝；并发修订比较有效；文件发布和索引写入中断可恢复；没有未验证产物被引用。

## T08：预测与复盘兼容

范围：`service.prediction`、`enrich_detail`、`predictor.py`、`briefing.py`、存储、结算与 AI 复盘读入适配。

- 新预测以足球概率为主体，市场参考独立；经过核验的比赛状态与体彩在售条件解耦。
- 先固定模型、选用/比赛/规则/所引用映射修订和输入再计算；提交时短临界区复核，数据库最终校验与插入同事务。换模/改期操作遵守同一跨进程并发约束，不因无关实体变更拒绝归档，训练长锁不阻塞当前模型正常预测。
- 新 schema 追加归档，旧原文及输入不变；解析旧市场主结果和足球附加结果，按类型分别评估。
- 结算绑定目标和正式结果版本；正式修正追加对照；多次预测采用预先固定的前瞻采样规则，不能挑最好结果。
- v1 写入口不能绕过新服务；旧客户端不兼容时明确要求更新，而非误写新格式。

验收：无赔率可归档基础足球预测，无模型不能归档市场冒充；同键幂等和同键异参拒绝；换模/改期/开赛期间不产生不一致归档；旧摘要不变；结果修正/多版本统计和 LLM 仅赛后约束通过。

## T09：界面联调

范围：拆分 `ModelWorkspace.vue`，更新 `api.js`、查询读模型和比赛详情组件。

- 落实六入口原型；每页绑定明确对象，不再拼“当前模型+最新候选成绩”。
- 概览固定日期、目标、统计时点、来源范围及分母，未知单列；身份未映射/缺模型比赛不能被隐藏。
- 数据集显示可追溯差额；训练界面提供单独任务及显式实验编排，展示父子阶段，无默认不透明全算法运行。
- 保留必要研究/数据限制，详细版本与证据入抽屉；无数据、过期、失败、冲突、部分能力均有状态。
- 使用独立构建输出进行视觉/交互验证；还不替换用户正在看的静态文件。

验收：每个数字可对账，错误不会变成就绪；切换赛事不串响应；表格单行、移动端局部滚动；笔记不丢；构建验证未改变当前服务资源。

## T10：真实试点与覆盖审计

范围：亚冠登记/采集/数据/训练新产物和真实审计，不改日韩既有选用。

- T01 已提前评估来源；补齐合格历史、身份/阶段/90分钟规则及目标球队样本，不混入亚冠二级赛事或国内赛果凑数。
- 独立训练与评估生成候选，列质量限制。模型选择保持独立，按实际批准的执行范围进行，不因训练完成自动选用。
- 对执行时仍未开赛的目标比赛验证真实输入与预测；原“今天”的比赛已开赛时不补造赛前归档。
- 动态核查销售日与北京时间自然日的全部已收录比赛、分页和新增/改期，逐场列资料、模型、能力与原因。

验收：真实来源→合格数据→本赛事产物→合规前瞻预测有证据才称试点闭环。任何外部缺口列阻塞对象、缺多少、影响哪些任务；不以更换试点、放宽阈值或合成数据替代。

## T11：综合验收、迁移与发布

范围：副本演练、真实增量迁移、独立构建与发布切换、当前预览、验收报告。

- 用主方案20项场景运行针对性测试与回归；模拟测试限定独立存储，不注入产品数据库。
- 验证迁移幂等、旧产物/归档/笔记完整性、配置和指针单一权威、服务中断与恢复。先在副本运行再真实切换。
- 独立输出构建完成后再发布；原子切换入口并保留旧资源/读取兼容期。旧写入口不能绕过，用户当前标签在无未保存输入风险时验证资源更新。
- 实现切换成功后更新现行系统契约，不提前把新准入标为已生效。
- 回退关闭新写入，保留新增归档/任务，回到兼容读取；存在新数据时不覆盖旧备份。当前标签不可访问则该验收项明确未完成。

建议测试入口：后端 `python -m unittest discover -s tests`、前端 `npm test`、Playwright 和真实来源审计。当前 `npm run build` 会直接改静态服务目录，实施时先提供不发布的构建方式再用作验证。

验收报告分开：工程完成、迁移兼容、亚冠闭环、日韩保护、其他赛事覆盖、前瞻效果积累。任何历史内容被无说明修改、跨赛污染、时间泄漏、市场冒充模型或不一致归档均阻止宣布完成。

## T12：后续增强

范围：球员档案、归属/租借/转会、赛事报名、停赛、伤病、预计/确认阵容、历史 xG 与其他增强特征。
