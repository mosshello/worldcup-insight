# 改造方案复核记录

日期：2026-11-04。复核对象：方案 v1.1 与任务 v1.1。结果：重整为 v2，仍待核对，未实施。

本记录区分“方案已经纠正”和“程序已经验证”。以下修订均为设计修订，不能当成代码测试通过。旧稿保存于 `.design/football-data-model-refactor/archive/`。

## 发现的问题与处理

| 编号 | 原方案缺陷 | v2 决策 | 验收归属 |
|---|---|---|---|
| R01 | 将一次按钮调度多项任务本身当成错误，默认要求用户操作多个按钮 | 任务边界必须独立，界面允许显式实验编排；父任务列清阶段和依赖，不要求机械地点击五次 | T06、T09 |
| R02 | 训练、固定产物测试、滚动更新策略和最终重训仍存在报告归属歧义 | 分别引用 artifact_id、protocol_id、fold_id；最终重训仅关联策略依据，直接前瞻结果单独统计 | T06、T07 |
| R03 | 把三赛季/300场等旧阈值泛化成所有模型与操作的共同定律 | 先保留旧正式工作流政策，按数据准备、比较、评估和选用分配检查；小样本研究不得自动升级观察模型；政策变更单独版本化 | T04、T05、T06、T07 |
| R04 | 没说清固定模型预测时，Elo/近期特征是冻结还是持续更新 | 输入规范必须声明特征状态更新方式；旧产物保持旧语义，新动态输入需新协议评估，不暗中换成实时特征 | T05、T08 |
| R05 | “模型可计算”容易被理解为效果合格或生产可用 | 分开数据准入、技术可用、研究评估、观察选用、前瞻证据；本期只承诺研究/观察，不虚构生产发布标准 | T07、T09 |
| R06 | 一期同时迁移赛事配置与模型选用权威，范围和回退风险过大 | 保留现有配置与文件注册表作为唯一权威；新增身份/任务/问题表。操作统一经服务；索引与审计可重建，不搞双主写入 | T02、T07、T11 |
| R07 | 只说旧模型不可变，却没有解决按当前规则重新校验旧产物会使其失效 | 旧产物完整性/历史适用政策与当前新训练准入分离；停训不等于停用或不可查看历史；安全性撤销需要显式理由 | T04、T07 |
| R08 | 未说明数据库、文件产物和指针跨存储提交失败后的状态 | 先发布不可变产物，再更新单一权威指针；中断可对账恢复。未完整发布不得标可选；不承诺跨存储原子事务 | T06、T07、T11 |
| R09 | 比赛/选用修订检查后仍可能在写入前变化 | 写入采用短临界区和版本比较；同服务的变更共用锁，数据库内最终检查与归档同事务。明确上游观测延迟边界 | T08、T11 |
| R10 | 单赛事导入“拒绝其他赛事”和现有批量导入按赛事筛选的契约冲突 | v2 单赛事接口严格拒绝混入；旧批量接口显式分区/报告，不静默丢弃。模型使用的样本始终隔离 | T04、T08 |
| R11 | 初评、正式结果、推导标签、旧市场参考、旧足球附加结果的复盘关联不完整 | 保存结果版本及 target_definition；新旧归档只读解析、按类型/模型/玩法分别评估；正式修正追加，不覆盖 | T08、T11 |
| R12 | 新赛事数据可行性验证过晚，可能先做完框架才发现无法训练 | T01 先核查亚冠来源、赛制、球队样本和使用范围，形成可行性清单；有阻碍时提前报告，不用其它赛事替代验收 | T01、T10 |
| R13 | 用单一可预测比例混合销售日/自然日、未知状态与资料完整度 | 固定日期、目标、统计时点和分母，未知单列；资格与资料覆盖独立；不把缺模型比赛移出分母 | T09、T11 |
| R14 | 把生产 build 当普通验证，忽略其清空当前静态目录、破坏旧 SPA 的风险 | 先独立输出构建；切换时保留旧资源及旧读取接口，关闭旧写入绕过；当前用户标签必须检查 | T09、T11 |
| R15 | T10 外部条件可能阻塞，却同时被写成“系统完成”的硬前提 | 分开工程验收和赛事闭环验收；逐项列状态。未完成亚冠闭环时不宣布用户整体目标完成 | T10、T11 |
| R16 | 规则按阶段适用、球队样本、模型支持玩法与名单增强边界仍模糊 | 先基于明确赛季/阶段/90分钟/场地政策接入；单回合、两回合、中立或新球队不支持时明确拒绝相应预测，不默认套主场参数 | T01、T02、T05、T10 |

## 尚未被实际证明的事项

- 亚冠目标球队是否具备足够的同赛事、同口径历史样本；必须依赖实际来源覆盖审计。
- 所有旧算法的历史/实时特征完全等价、每个时间边界都无泄漏；必须通过 T05 的针对性测试，不能仅凭阅读代码保证。
- 新接口、迁移、并发检查、页面切换可用；尚未实现，不能标已验收。
- 模型的独立前瞻质量；已有历史研究成绩不能代替未来实测。

## 本次审查结论

v1.1 不宜直接用于实施：其任务、状态、迁移和评估边界仍有互相冲突的地方。v2 替换主稿和任务表，收窄不必要迁移，并补充可执行场景矩阵。v2 是经过再次核对的设计，不是“已无漏洞”的保证；进入实施前仍由用户核对，进入实施后每项通过代码、隔离测试和真实来源证据确认。
