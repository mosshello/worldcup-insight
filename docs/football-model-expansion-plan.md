# 足球模型扩展与训练流程梳理

日期：2026-11-01。状态：执行中；统一训练与两个新增候选已实现，实际进度见文末。其余规划不能视为已完成能力。

本方案遵守 football-system-contract.md。最初仅梳理；用户随后授权继续执行。训练只生成研究候选，不自动变更观察模型或历史预测。实现以本文件和系统契约共同验收。

## 1. 当前实际状态

- 市场基线：由完整体彩 SP 计算市场参考概率，不是训练出的足球模型。
- 控制台训练：180/365 天时间衰减 × 泊松/两阶段低比分修正，共四种参数候选；训练产生候选，单独选用观察。
- 探索对比：泊松、两阶段修正、联合 Dixon–Coles、Elo 逻辑回归、CatBoost，共五种方法。目前由独立命令运行，页面训练按钮不包含全部方法。
- Elo 逻辑回归和 CatBoost 当前只输出胜平负；不具备总进球、比分和半全场能力。
- 进球模型的半全场目前通过条件半场比例推导，不是已独立验证的动态半场模型。
- 当前缺少可用于完整历史比较的盘口快照，也没有将 xG、完整伤停、阵容和外盘用于训练。
- 已查看过的历史测试集属于探索材料，不能继续调参后再作为新模型独立验收证据。

需要解决的核心问题是训练入口、输出能力、数据版本和评估口径不统一，而不是增加页面上的模型数量。

## 2. 模型与算法的分类

业务区分市场参考、足球预测、赛后解释。算法、参数候选、训练产物分别管理，避免把一个算法的多个参数组合列成多个业务模型。

| 方法 | 当前状态 | 下一步安排 | 输出能力 |
|---|---|---|---|
| 市场基线 | 已有 | 保留为独立参考和评估对照 | 仅有完整赔率的玩法 |
| 泊松 / 两阶段修正 | 已有 | 保留基准，统一登记；准确标识两阶段修正 | 全场比分分布及其派生玩法 |
| 联合 Dixon–Coles | 探索实现 | 接入统一训练、产物与评估协议后作为候选 | 全场比分分布及其派生玩法 |
| Elo 逻辑回归 / CatBoost 分类 | 探索实现 | 保留胜平负对照，不扩充为虚假的全玩法模型 | 胜平负 |
| LightGBM 进球回归 + 比分分布 | 未实现 | 新增研究候选；日职优先验证，韩职可独立训练比较 | 双方预期进球、比分分布及派生玩法 |
| 动态贝叶斯进球模型 | 未实现 | 新增研究候选；韩职优先验证，日职可独立训练比较 | 随时间变化的攻防、比分分布及派生玩法 |
| 半场/下半场条件模型 | 未实现 | 独立能力模块，半场数据验收后再验证 | 联合半全场概率 |

只规划两类新增主候选。日职、韩职优先顺序来自研究方向，不预先指定哪个算法获胜。动态贝叶斯先确定一个可复现的进球分布实现，不一次堆叠所有分布变体。Skellam 净胜球模型可留作专项对照，但不能单独生成总进球和精确比分。

不直接载入外部项目权重；先审查许可、特征时点与训练定义，再在本地独立数据上复现。暂不增加自动集成、自动调参发布或基于大模型的赛前预测。

## 3. 赛事归属与隔离

- 一个算法可以支持多个赛事，但每个赛事分别持有数据版本、参数、运行记录、模型文件、评估报告、观察选择。
- 存储主路径继续为 competitions/<competition_id>/，产物再记录 algorithm_id、run_id、dataset_digest、feature_version、target_definition、training_cutoff、supported_markets。
- 日职普通联赛、特殊赛制阶段、韩职分组阶段须有明确规则和标签；是否允许同一赛事内不同阶段共同训练，要事先确定策略并分阶段评估。
- 欧冠、天皇杯等另建赛事数据和模型选择；不能套用国内联赛参数。比赛类型未知时禁止猜测。
- 模型能力配置由实际实现和数据验收决定，不靠模型名称推断。不支持的玩法明确缺失，不从其他算法静默拼接。

## 4. 数据先于模型

| 数据层 | 内容 | 准入要求 |
|---|---|---|
| 赛果与身份 | 赛事、赛季、阶段、双方、时间、90 分钟比分、半场比分 | ID 精确映射；加时和点球分离；冲突记录隔离 |
| 赛前基础特征 | 同赛事近期攻防、主客差异、Elo、样本量、休息时间 | 每条训练样本只读取该时点之前可用事实 |
| 增强基本面 | 历史射门、射正、xG、阵容、缺阵、人员变化 | 有来源、适用赛事、发布时间或明确历史可用假设；缺失不能填成无伤停或零能力 |
| 市场 | 体彩五玩法及可取得的外盘 | 保留机构、玩法、让球/大小球线、来源时间、采集时间和状态，分别比较，不直接混合 SP |

先在所有候选共享的基础特征上比较算法，再在同一算法上逐组增加基本面，以区分算法收益和数据收益。增强特征覆盖较少时同时报告全体可预测覆盖率和共同样本成绩，不拿不同比赛集合直接排名。

历史赛季最终 xG、赛后阵容或全场射门不能回填成赛前已知数据。后补事实用于历史模拟时，须说明可用时间假设；当前实时预测采用实际可用时间。

外盘暂作独立参考和对照。历史时点快照不足时不进入训练，不声称已战胜市场。赔率过期、缺项或盘口含义不明时，阻断对应市场比较和选择；足球概率是否仍可提供按它自身输入状态判断。

## 5. 统一训练与评估流程

1. 选择赛事和目标玩法，检查候选方法兼容性。
2. 验收数据，固定不可变数据版本、特征版本、预测时点和标签定义。
3. 在验证前固定时间切分、候选范围、调参预算、校准方式及通过标准。
4. 按时间滚动训练；每场的特征可用截止、拟合截止和预测截止分别记录，不能穿越预测时点。
5. 验证段选算法、参数和校准；测试段只评估冻结方案，不用于选择。已反复查看的历史段只标探索；真正未查看的留出数据不足时使用后续前瞻观察。
6. 输出逐场概率、分玩法指标、覆盖率、失败原因和产物摘要；失败任务不产生可选成功模型。
7. 训练完成仅产生候选。进入前瞻观察需要独立操作；观察不等于通过发布验收。
8. 新比赛冻结并归档预测。结果确认后程序结算，赛后大模型仅解释证据。

现有 benchmark 与控制台训练应复用同一方法登记、特征构建、时点规则和评估器。命令行和页面只是同一训练服务的不同入口，不再维持两套实现口径。

## 6. 多玩法输出与检验

| 玩法 | 输出依据 | 单独检验 |
|---|---|---|
| 胜平负 | 比分分布汇总或明确标识的分类器 | Log loss、Brier、概率校准、覆盖率；命中率辅助 |
| 总进球 | 比分分布按总和汇总，按体彩 0—6、7+ 映射 | 分类概率误差、进球均值偏差、分档校准 |
| 比分 | 联合比分分布与尾部归集 | 实际比分概率、概率误差、固定 Top-N 覆盖 |
| 让球胜平负 | 同一比分分布 + 当时实际体彩让球线 | 对应三分类概率；没有历史线不虚构回测 |
| 半全场 | 半场和全场的联合关系 | 九项概率误差、半场/全场一致性；不直接相乘 |

五玩法不要求五个互不相关的模型。全场相关玩法尽量由同一分布生成，避免胜平负、总进球、比分彼此矛盾。分布必须归一、非负，截断尾部必须正确处理；半场进球不得超过对应全场进球。

模型概率、候选选择策略、市场比较是三个独立层。双选、Top-N、是否放弃须固定规则后评估；不能赛后变更选项数量或只统计挑中的比赛。策略变更单独版本化。

## 7. 验收与替换标准

- 同赛事、同比赛、同预测截止比较，样本外概率误差与校准优先；分赛季、阶段、主客及玩法检查。
- 报告相对现有模型和可比赔率基线的差异、样本量及不确定区间。区间按轮次或时间块估计，避免假设全部比赛完全独立。
- 精度差异、覆盖率、可接受校准偏差和运行成本的具体阈值在新验证开始前确定并保存；不看过结果再改门槛。
- 尚无市场历史覆盖就标为无法验证市场优势；缺失某玩法数据就不宣称该玩法通过。
- 新增特征须有消融对比；贝叶斯模型须检查采样收敛和后验预测，优化方法须报告拟合失败。
- 隔离、时间泄漏、产物完整性、概率一致性和原有预测/结算回归必须通过。
- 无明确增益时保留现有观察模型或停止其观察，不为了新增而替换；既有模型表现不足也不能因它是默认模型而称其合格。

## 8. 页面调整范围

- 先选赛事。模型列表显示名称、支持玩法、训练截止、评估结论、当前用途和操作。
- 统一“训练”入口：选择兼容方法，展示真实数据缺口和任务进度。
- 模型对比只比较同目标、同样本的指标；市场参考独立标识。
- 状态分别记录任务成功/失败、数据验收、评估通过与否、候选/观察/停止，避免一个“可用”掩盖多种状态。
- 训练数据、特征、参数、缺失项和逐场记录放入详情抽屉。主表单行、直角、保持 TDesign 规范。
- 不新增演示成绩、宣传准确率或没有真实实现的模型卡片。

## 9. 实施依赖顺序

1. 核查身份、比分口径和时点，形成可追溯数据清单。
2. 统一已有训练和探索对比，建立方法能力登记与产物协议。
3. 用基础特征实现两个新增候选，各赛事独立运行探索比较。
4. 增强基本面按实际覆盖逐项接入、验收和消融；同步积累盘口快照。
5. 单独完善半全场能力与多玩法一致性验证。
6. 冻结候选方案后开展独立评估和前瞻观察，再决定各赛事是否替换。

## 执行记录：2026-11-01

已完成：

- 统一控制台与两个 CLI 训练入口；7 种方法、9 组配置共用时点切分、评估和候选保存。
- 增加全场玩法/仅胜平负目标；不兼容的分类器只作对照，不参与全场目标选优。
- 实现 LightGBM 进球候选和动态 Gamma–Poisson 候选，均有明确的 JSON 参数保存与恢复；不使用外部项目权重。
- 动态 Gamma 是时间折扣的近似共轭滤波：攻防乘数使用 Gamma 状态，更新时对对手状态取均值，预测混合 512 次固定种子后验抽样。不等同原论文的联合贝叶斯 MCMC，也未声称复现论文成绩。
- LightGBM 使用与现有分类对照相同的七个 Elo/近期进失球/样本量特征。没有新增 xG、伤停、阵容、外盘。训练为固定 100 轮、深度 3、7 叶、学习率 0.03、Poisson 目标和单线程。
- 日职 1,391 场、韩职 884 场分别完成真实探索回测，旧观察指针和此前数据、模型文件哈希不变。
- 页面显示方法、能力、目标、实际评估与详情，支持无预期进球的分类器分析展示。

尚未完成：新增有历史时点证明的外部基本面/盘口、独立半场模型、增强特征消融、时间块置信区间、未查看测试段或前瞻样本验收。当前半全场仍为条件二项分配。不得把上述进度表述成整套方案全部完成或模型可靠性达标。
