# 历史数据采集与入库

运行规则与命令以 [功能边界与执行约束](football-system-contract.md) 为准。赛事独立数据、训练、模型选用已落实；下文保留来源调查及迁移过程，不能据此恢复全局共用模型。

历史训练库覆盖整个联赛；业务比赛仍由体彩开售列表决定。两个统计已在“数据与模型”页面分开。

## 范围

| 联赛 | 完整历史赛季 | 当前赛季 | 暂未纳入 |
|---|---|---|---|
| 日职 | 2023、2024、2025、2026 百年构想 | 2026/27 | — |
| 韩职 | 2023、2024、2025 | 2026 | 升降级附加赛不混入 K1 联赛 |

2026 数据不是被旧赛季替代。旧赛季用于增加历史样本，当前赛季补充近期表现；页面优先显示最新赛季。

## 当前实现

- 从 500 公开赛季导航发现阶段与轮次，串行采集基础赛果，保存稳定比赛/球队 ID、阶段、半全场比分、赛程时间、来源和响应摘要。
- 排除未完赛、无效比分、未来已完赛记录；核对历史赛季总场次、球队数量及每队场次。只做结构核验的记录不算双源核对。
- 将此前 12 场官方样本的身份和比分对应到待验收库。时间差异继续保留，不静默覆盖。
- 百年构想按独立赛季 `2026-special` 维护，分东西区各 90 场及十组排名赛各 2 场，合计 200 场。每队应有 20 场；分组阶段每队 18 场。忽略“排位赛”汇总入口以免与十个具体阶段重复。
- 百年构想增加 12 场官方检查：两场分组点球赛和全部十场排名赛次回合。解析官方页面提供的进球事件，用 45/90 分钟（含补时）划分半场和常规时间，核对事件总数与官方含加时比分；点球单列。缺失进球事件、未知时段、身份不唯一或官方比分不符均阻止该赛季入库。这仍是抽查，不代表其余 188 场已双源核对。
- 已完成历史赛季复用缓存；当前赛季按天保存快照。重新运行覆盖同一个待验收快照，不追加重复记录。
- 403/429 不自动重试；同一采集实例连续三次服务端/连接错误后暂停新的网络请求，仍允许读取缓存。
- 待验收库与 `club_history.json` 隔离。网页展示采集状态，只有正式训练库的数据计入“已入训练库”。

## 命令

```powershell
.venv/Scripts/python.exe -m worldcup_mvp.console.history_pipeline
.venv/Scripts/python.exe -m worldcup_mvp.console.history_pipeline --offline
```

默认产物：`data/training/history_staging.json`、同名 `.md` 报告及 `data/training/history_raw/` 原始响应。均为本地数据，受现有 Git 忽略规则保护。

当前赛季会包含尚未结束的轮次，因此不拿整季应有场次要求当前完赛样本；失败请求必须显式显示为待核查，不能据已返回的少量记录宣称采齐。

## 授权数据导入规则

准备导入前需要处理采集错误、数据冲突及时间差异，确认来源使用依据并明确接受的数据版本。程序不会自行生成授权声明。

显式 manifest 必须包含：`dataset_digest`、`quality_accepted: true`、`training_permitted: true`、`license_reference`、`source_url`、`availability_policy`。这些是使用方提供并可追溯的验收信息，不代表软件对权利作法律认证。

可选 `seasons` 明确选择已通过验收的赛季，例如 `['kr.k1:2023', 'kr.k1:2024', 'kr.k1:2025']`（JSON 文件使用双引号）。单个当前赛季采集失败不应阻断其他已经验收的赛季；未指定则检查全部采集范围。

授权 manifest 适配器支持 `availability_policy: kickoff_plus_7_days_assumption`：假设赛果在赛程时间七天后可用于历史训练。它是保守回测假设，不是来源提供的发布时间。最近七天的样本暂不进入这一口径；模型页面显示该假设。精确历史信息时点仍需有时间戳的数据来源。

```powershell
# 生成候选文件，仍不改动正式训练库
.venv/Scripts/python.exe -m worldcup_mvp.console.history_pipeline --manifest <manifest.json>
# 验收候选后显式入库，不自动训练或启用模型
.venv/Scripts/python.exe -m worldcup_mvp.console.history_pipeline --manifest <manifest.json> --import-prepared
```

准备步骤会重算数据摘要，拒绝篡改或与验收版本不符的数据。输入未完成、结构核查失败、比分冲突、未处理时间差异和不明确的时间口径都会拒绝入库。

没有可信观察时间的汇总赔率不进入训练或收益回测；本次没有扩展历史赔率覆盖，也没有切换生产模型。

## 本地实验训练

2026-11-01 用户明确要求补充日韩基本面、训练并预测今日比赛，已按该请求完成本地实验。该模式保留 `rights_status=unverified`、`commercial_use_permitted=false`，不写入虚构的第三方授权凭据，也不自动发布商用模型。

- 2,276 条采集记录中，排除 `500:1077413` 的开赛时间待核查记录，实际训练库 2,275 场。剩余记录通过结构校验和官方抽查，不声称全量双源核验。
- `historical_7_day_lag_or_observed` 使用历史赛果七天延迟假设；若最近比赛已在采集时观察到，则以实际采集时间进入训练。回测每个截点仍只读取当时可用的记录，不把今天的采集时间倒填成历史实时发布时间。
- 校验完整性和比分冲突仍会阻止入库；只允许明确排除未解决的开赛时间记录。
- 基本面按已匹配赛程的球队 ID 提取最近联赛赛果、分别选取主客场近 5 场、当前赛季累计和近 5 次交锋。联赛间隔不冒充完整休息时间；未经确认的伤停和首发保持未知。
- 新体彩场次通过联赛、赛季、双方精确别名和开赛时间匹配赛程。模型已有该历史球队时可复用参数，不为每场比赛重新训练；无唯一匹配或球队少于 5 场历史时拒绝模型预测。

```powershell
# 更新公开基础赛果与赛程；保留原始响应和采集时间
.venv/Scripts/python.exe -m worldcup_mvp.console.history_pipeline
# 根据已存在的明确本地实验请求建立训练库；不代表来源授权
.venv/Scripts/python.exe -m worldcup_mvp.console.research_dataset --request-reference "2026-11-01 用户要求本地训练日韩模型"
# 在页面点击“训练与回测”，或显式运行同一流程
.venv/Scripts/python.exe -m worldcup_mvp.console.training --evaluate
```

训练比较 12 组配置，在验证集选参后对独立测试集进行逐周滚动预测。日职、韩职分别报告结果，并与均匀概率基线对照；没有可信历史赔率时不报告超越市场或收益率。今日报告见 `docs/reports/2026-11-01-jk-predictions.md`。
